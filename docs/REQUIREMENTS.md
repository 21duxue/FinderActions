# FinderActions 需求说明

## 1. 产品定位

FinderActions 是一个 macOS Finder 右键菜单增强工具。

它解决四个高频但原生 Finder 没有直接提供的能力：

1. 在当前 Finder 目录创建文件
2. 在当前 Finder 目录打开终端
3. 复制当前 Finder 目录或选中项的路径
4. 复制选中项名称

v1 的目标不是做“万能 Finder 工具”，而是把这四个动作做到可靠、清晰、可维护。

## 2. v1 范围

### 2.1 必须做

#### New File Here

- 在 Finder 右键菜单中提供 `New File Here…`
- 默认弹出原生文件名输入框
- 默认文件名预填为 `Untitled.txt`
- 用户可直接回车创建
- 支持输入任意合法文件名和扩展名
- 重名时自动追加 ` 2`
- 不覆盖已有文件
- 创建成功后在 Finder 中选中新文件
- 创建失败时显示明确错误，例如：
  - 文件名非法
  - 无权限
  - 目标目录不可写

#### Open Terminal Here

- 在 Finder 右键菜单中提供 `Open Terminal Here`
- 默认打开当前 Finder 目录
- 如果当前选中的是文件，打开该文件所在目录
- 固定使用 Apple Terminal
- 不提供终端选择
- 不检测或管理第三方终端
- 如果 Apple Terminal 无法启动，显示明确错误

#### Copy Path Here

- 在 Finder 右键菜单中提供 `Copy Path Here`
- 默认复制当前 Finder 目录的 POSIX 路径
- 如果选中了文件或文件夹，复制选中项的路径
- 如果选中多个项目，复制多个路径，并用换行分隔
- 复制成功后给出行内反馈，不弹系统级提示框
- v1 只复制原始 POSIX 路径，不做：
  - URL 路径
  - Windows 路径
  - 自动加引号
  - Shell 转义路径

#### Copy Name Here

- 在 Finder 右键菜单中提供 `Copy Name Here`
- 如果选中了文件或文件夹，复制选中项的名称
- 如果没有选中项，复制当前 Finder 目录的名称
- 如果选中多个项目，复制多个名称，并用换行分隔
- 名称不包含路径
- 复制成功后给出行内反馈，不弹系统级提示框

## 3. v1 不做什么

以下能力明确不属于 v1：

- 云同步
- 账号系统
- 复杂模板系统
- 自动更新
- 网络访问
- 主题系统
- 全局快捷键
- 打开任意应用
- 打开编辑器
- 复制 Shell 路径
- 父级目录跳转
- 自定义菜单排序
- 自定义图标
- 多 Finder 窗口管理

说明：
- `New Folder Here` 不做，因为 macOS Finder 原生已有新建文件夹能力
- `Copy Shell Path Here` 不做，避免引入引号和转义策略的额外复杂度

## 4. 用户故事

### 4.1 New File Here

1. 用户在 Finder 中右键空白区域
2. 选择 `FinderActions ▸ New File Here…`
3. 弹出原生输入框，预填 `Untitled.txt`
4. 用户直接回车
5. 在当前目录创建一个空文件
6. Finder 自动选中新文件

### 4.2 Open Terminal Here

1. 用户在 Finder 中右键空白区域或选中一个文件
2. 选择 `FinderActions ▸ Open Terminal Here`
3. FinderActions 打开 Apple Terminal
4. 终端启动后进入当前目录或选中文件所在目录

### 4.3 Copy Path Here

1. 用户在 Finder 中右键当前目录或选中项
2. 选择 `FinderActions ▸ Copy Path Here`
3. 路径被复制到剪贴板
4. 界面显示“已复制路径”

### 4.4 Copy Name Here

1. 用户在 Finder 中选中一个或多个文件
2. 选择 `FinderActions ▸ Copy Name Here`
3. 文件名被复制到剪贴板
4. 多选时，每个名称占一行

## 5. 交互设计要求

### 5.1 菜单结构

v1 同时支持两种菜单结构，默认使用子菜单。

默认结构：

```text
FinderActions ▸
  New File Here…
  Open Terminal Here
  Copy Path Here
  Copy Name Here
```

平铺结构：

```text
New File Here…
Open Terminal Here
Copy Path Here
Copy Name Here
```

设置窗口提供 `子菜单 / 平铺` 切换。
切换后立即生效，不需要重启 Finder。

选择理由：
- 子菜单避免污染 Finder 顶级菜单
- 平铺满足偏好单次点击直达的用户
- 两种结构都只包含 v1 的四个动作

### 5.2 New File Here 交互

- 必须弹出输入框
- 默认文件名为 `Untitled.txt`
- 输入框应支持：
  - 直接回车创建
  - 修改文件名
  - 取消
- 不支持模板管理
- 不支持记住上一次文件名
- 不支持自动打开新文件

### 5.3 设置窗口

v1 设置窗口应保持精简，只包含：

1. 四个功能的启用开关
2. 菜单结构：子菜单 / 平铺
3. 新建文件默认名
4. Finder 扩展启用状态提示
5. 打开系统扩展设置的按钮
6. 中文 / English 语言切换，默认中文

不应包含：
- 主题
- 自动更新
- 账号
- 快捷键
- 模板管理
- 菜单排序
- 复杂搜索

### 5.4 反馈方式

- 文件创建成功：在 Finder 中选中新文件，可使用轻量提示
- 终端打开成功：无额外提示
- Apple Terminal 无法启动：显示明确错误
- 路径复制成功：显示“已复制路径”
- 名称复制成功：显示“已复制名称”
- 权限不足：显示明确错误，不静默失败

## 6. 边界条件

### 6.1 目标目录

- 支持本机启动盘内的目录
- 不支持外接盘
- 不支持 SMB
- 不支持 iCloud Drive、OneDrive、Dropbox、Google Drive 等 File Provider 目录
- 如果目标路径位于不受支持的位置，v1 不承诺显示菜单或完成操作

### 6.2 文件名

必须处理：

- 空文件名
- 只有空格的文件名
- 非法字符，如 `/`
- 已存在的文件名
- 隐藏文件名，如 `.env`
- 文件名包含中文、空格、标点
- 文件名以点结尾
- 文件名过长

### 6.3 多选

- `New File Here` 只对当前目录生效
- `Open Terminal Here` 对当前目录或选中文件所在目录生效
- `Copy Path Here` 支持多选，路径之间用换行分隔
- `Copy Name Here` 支持多选，名称之间用换行分隔

### 6.4 系统权限

- 用户可能尚未启用 Finder 扩展
- 设置窗口必须能显示扩展启用状态
- 设置窗口必须提供打开系统扩展设置的入口
- 不应假设用户知道系统设置在哪里

## 7. 非功能需求

### 7.1 安全

- 不做网络访问
- 不做遥测
- 不做账号系统
- 不做自动更新
- 不拼接 shell 命令
- 不拼接 AppleScript 字符串
- 路径和文件名必须通过参数数组或系统 API 传递

### 7.2 性能

- 右键菜单响应应保持接近原生 Finder
- 设置窗口启动应快
- 不应常驻大量资源

### 7.3 可维护性

- 核心逻辑应拆到独立模块
- FinderSync Extension 不应承载业务逻辑
- UI 不应直接依赖 FinderSync API
- 应优先测试纯逻辑模块

## 8. 验收标准

### 8.1 New File Here

- 能在当前 Finder 目录创建空文件
- 默认文件名为 `Untitled.txt`
- 用户可以修改文件名
- 重名时自动追加 ` 2`
- 非法文件名会被拒绝
- 创建成功后 Finder 选中新文件
- 不覆盖已有文件

### 8.2 Open Terminal Here

- 能打开当前目录
- 选中文件时能打开其所在目录
- 固定使用 Apple Terminal
- Apple Terminal 无法启动时有明确提示
- 不产生命令注入风险

### 8.3 Copy Path Here

- 能复制当前目录路径
- 选中文件时能复制文件路径
- 支持多选路径
- 复制成功后有反馈
- 不额外修改路径格式

### 8.4 Copy Name Here

- 选中文件时能复制文件名
- 选中文件夹时能复制文件夹名
- 没有选中项时能复制当前目录名
- 支持多选名称
- 复制成功后有反馈

### 8.5 设置

- 能开关四个功能
- 能选择子菜单或平铺结构
- 能修改默认文件名
- 能查看扩展启用状态
- 能跳转到系统扩展设置

## 9. 暂不实现的能力

以下能力可以出现在原型或后续版本讨论中，但不属于 v1：

- 自定义菜单项顺序
- 文件模板
- 打开编辑器
- 打开任意应用
- 父级目录跳转
- 全局快捷键
- Shell 路径复制
- 新建文件夹

## 10. 未决问题

1. `New File Here` 是否需要记住上一次使用的扩展名？
2. `Copy Path Here` 是否需要在后续版本支持自动加引号？
3. 是否需要在后续版本支持更多终端？
4. 是否需要在后续版本支持外接盘和 SMB？

## 11. 语言要求

- v1 同时支持中文和英文
- 默认语言为中文
- 用户可切换到 English
- 切换语言不需要重启应用
- 语言设置只在本地保存
- 不支持其他语言
- 所有菜单、设置、提示和错误信息都必须有中英文文案
- 错误信息必须写清楚发生了什么和用户下一步可以做什么，不使用营销话术
